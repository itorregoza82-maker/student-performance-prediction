# Student Performance Prediction System

A classroom prototype that uses historical Mathematics student records from the UCI Student Performance dataset to estimate whether a record belongs to the **AT RISK** or **NOT AT RISK** category.

> **Responsible-use note:** This project is an educational demonstration. A model prediction is not a diagnosis and must never be the sole basis for decisions about a real student. Faculty should review relevant context and provide appropriate support.

## Problem statement

Academic risk may be noticed only after poor results have occurred. This prototype explores whether available student indicators and earlier-period grades can help flag historical records for further review.

## Dataset source

- UCI Machine Learning Repository: [Student Performance](https://archive.ics.uci.edu/dataset/320/student+performance)
- Dataset ID: 320
- File used: Mathematics (`student-mat.csv`)
- The UCI dataset contains student demographic, social, school-related, and academic attributes.

The training script retrieves the dataset using `ucimlrepo` and saves the Mathematics data as `student_data.csv`.

## Prediction target

- `G3 < 10` → `AT RISK` (encoded as `1`)
- `G3 >= 10` → `NOT AT RISK` (encoded as `0`)

`G3` is excluded from all input features to prevent target leakage. `G1` and `G2` remain as predictors, following the laboratory instructions.

## Train and evaluate the model

Run this command from the project folder:

```bash
python train_model.py
```

The script:
1. Retrieves UCI dataset 320.
2. Combines the feature and target columns and saves `student_data.csv`.
3. Prints dimensions, first rows, data types, and missing values.
4. Removes duplicate rows.
5. Creates the binary target from G3 and excludes G3 from predictors.
6. Imputes missing values, scales numerical features, and one-hot encodes categorical features.
7. Uses an 80:20 stratified train/test split.
8. Trains a Random Forest classifier.
9. Prints accuracy, AT RISK precision, AT RISK recall, AT RISK F1-score, and the classification report.
10. Saves `student_model.pkl`, `model_evaluation.json`, and `classification_report.txt`.

**Do not copy or invent evaluation values.** Use the values printed by your own run and saved in `model_evaluation.json`.

## Run the Streamlit application

After training has completed:

```bash
streamlit run app.py
```

Open the local address displayed in the terminal (normally `http://localhost:8501`).

The application has three sections:
- **Dashboard:** dataset totals, average final grade, historical risk count, and grade distribution.
- **Dataset Preview:** records, data types, and missing-value information.
- **Student Prediction:** download a sample input CSV, upload a CSV, validate required columns, view predictions, and download results.

## Input CSV requirements

The upload must contain all predictor columns used during training. It should not require `G3`. If `G3` or other extra columns are included, the application ignores them during prediction. Missing predictor columns trigger an error message.

The easiest way to get a correctly structured file is to download **sample_prediction_input.csv** from the Student Prediction page.

## Limitations

- The data comes from two Portuguese secondary schools and may not represent another school, country, or student population.
- The data is historical and may not reflect current learning conditions.
- G1 and G2 are strongly related to G3; using them makes the task easier but means predictions are made after earlier grading periods.
- A classification result can be wrong and should be treated as a prompt for supportive human review, not as a final judgment.
- The model learns associations in the dataset and does not establish causes of academic performance.
- Model performance on the held-out test set does not guarantee performance in real-world use.

Create a **public** repository named `student-performance-prediction`. Then, from this project folder:


Replace `YOUR-USERNAME` with your GitHub username. If you already configured a remote, inspect it with `git remote -v` rather than adding a duplicate. Sign in through GitHub's approved authentication flow; never place passwords or personal access tokens in source files.
